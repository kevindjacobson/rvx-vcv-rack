# RVX prototype contract

The user approved building issue #13 on September 7, 2026: “Let’s get building. Orchestrate a team”. This authorizes the six-module prototype, dependency setup and validation. It does not assert that the complete LZX release plan or its fidelity gates have passed. Issues #2–#5 and #7–#9 retain their outstanding planning scope. Issue #6 delivered the [Memory Palace behavior sheet](MEMORY-PALACE.md); its unrun hardware and fidelity gates remain explicit.

Initial validation target observed locally: Apple M4, 16 GiB memory, macOS 26.2 (25C56), VCV Rack Pro 2.6.6 standalone, arm64. DAW compatibility is not inferred. SDK 2.6.6 mac-arm64 SHA-256: 29414e52417992cbafa47e30f947c3c0c7a34e5c424bb83c5a0af8c24840481f.

Prototype defaults: 720 × 480, 30000/1001 image ticks/second. This is a progressive working canvas; it does not implement NTSC interlace, blanking or composite timing. Four-channel float encoded RGB with straight alpha, top-left origin; fields have one float per active raster position. Intermediate finite signals remain signed and unclipped; display/Syphon export converts explicitly. CPU arithmetic is the initial measurable reference backend; Syphon uses an owned GPU context/device. GPU processing remains an evaluated expansion, not an implemented claim.

The six node kinds and typed ports are defined in src/core/Video.hpp. UI and native audio callbacks only capture topology/controls into RVX-owned state. The video worker owns processing, history and I/O; it never dereferences Rack module/cable pointers. Native video-port voltages are inert. UI cable snapshots preserve native wiring and Rack serialization. Syphon reception occurs before dependent operators; publication occurs after the completed graph so one I/O node can receive, process and publish without creating a false internal cycle. Acyclic nodes render within one tick. Delay outputs read previous state before all histories commit. Bypassed delay is a pass-through and therefore cannot break a cycle. Unpatched image inputs are black; unpatched field modulation is unity. Invalid connections yield empty input and diagnostics.

Parameter contract (zero-based indices):
- Test Image: 0 pattern (0 bars, 1 checker, 2 ramp, 3 raster phase probe), 1 phase speed in cycles/second, from −4 to +4. Speed is latched once per video tick and integrated into a continuous phase accumulator. Changing speed or pattern preserves phase; explicit module reset returns it to zero. Positive and negative speeds move in opposite directions; zero freezes phase. Bars scroll horizontally through the seven-color sequence; checker scrolls across its 64-pixel repeat; ramp advances and wraps at one (zero phase retains the original 0–1 endpoints). The raster probe adds the ordered sample position within the frame to the accumulated frame-start phase; its within-frame slope also follows speed. This probe is a timing diagnostic, not an NTSC oscillator.
- Signal Processor: 0 gain A (default 1), 1 gain B (default 0), 2 offset (default 0), 3 mode (0 mix, 1 field-to-grayscale, 2 red, 3 green, 4 blue). Image out is unclipped pointwise A*gainA + B*gainB + offset, modulated by the field when connected. Field out extracts the named component; mix defaults to red extraction. Field-to-grayscale explicitly combines the field into RGB with alpha one. Alpha is preserved from A for mix and is not voltage gain-modulated.
- CV Bridge: 0 mode (0 latched CV, 1 buffered audio-to-raster, 2 trigger field), 1 volts-to-field scale (default 0.1), 2 field offset. Rack audio/CV remain volts; default 10 V = 1 video unit. Capture short trigger edges as a counter, display each pending event for at least one tick. Audio producer timestamps are monotonic accumulated Rack sample time; resets increment epoch. Buffered raster conversion samples a documented completed audio interval with linear interpolation and one-tick buffering; no hardware genlock claim. The renderer anchors each audio epoch to the current video time when the first completed sample batch arrives, so bridges added later do not compare unrelated clock origins. Reset, sample-rate changes, Rack frame discontinuities, audio-input cable connection changes and queue-loss bursts start a new epoch. Each epoch denotes a continuous capture run; interpolation must not cross uncaptured gaps. This alignment is approximate and includes frame buffering; it is not device genlock. Pending events and sample history are bounded with counted overflow.
- Frame Delay: 0 clear button, 1 integer frame count (1–60, default 1). Existing patches that omit parameter 1 retain one frame. Native clear input port 1 captures rising gates independent of video rate. Clear/reset yields transparent black history before the next feedback read.
- Video Monitor: no processing controls; diagnostics only, shared engine continues without monitors.
- Video I/O: settings saved as source identity/application/name, publisher name, enable, missing-source policy. Source selection belongs on the main UI; SDK operations belong on its worker. Publisher names must be unique by default across module instances.

Renderer/backend construction and destruction occur on the same worker, including engine restart. Working-format changes invalidate incompatible history before any pixel reads. The 512 MiB preflight counts unique prior output/preview frames and estimates the new generation plus internal/backend working storage. Process RSS and external consumers retaining arbitrary generations are separate from this preflight.

The buffered-audio mapping follows the independent video clock until a newly captured batch cannot cover the mapped interval, or the producer leads that interval by more than one tick. With enough complete history it reanchors to the newest one-tick interval and counts the correction. This bounded recovery handles clock drift and Rack's non-device fallback scheduling; a correction can introduce an audio-to-image discontinuity, so it is not a genlock or seamless resampling claim. Incomplete batches remain bounded in history until an interval can be completed. After a previously rendered stream actually stalls, recovery additionally requires a full fresh interval beyond its last rendered endpoint; one new sample cannot authorize replay of the old interval. An unavailable interval produces a zero field, including when capture stops; it does not replay a stale partial image or apply the offset to missing data. Capacity evictions, queue drops and clock reanchors have distinct cumulative diagnostics. Ordinary trimming of already-consumed history is not reported as loss.

Bypass is latched once per video tick for every module. Test Image emits black/zero while its phase clock continues. Signal Processor passes Image A and extracts the selected component, ignoring gains and field modulation. CV Bridge emits zero and discards captures accumulated while bypassed. Frame Delay passes input immediately and cannot make a feedback cycle causal. Video Monitor displays black. Video I/O stops receiving and publishing and emits black. CV reset discards pending triggers and audio history, then reanchors the next capture epoch; dropped audio samples are counted cumulatively in its status.

Shared interfaces are reviewable starting points. Any required change must be coordinated between engine, Rack adapter and Syphon workers before integration. Panel names are RVX prototype utilities, not claimed LZX emulations. Memory Palace and dirty NTSC remain explicit later requirements.

## Adjustable Frame Delay (#18)

One frame is one progressive RVX image tick. At the default 30000/1001 rate, 1, 15, 30 and 60 frames correspond to about 33.367 ms, 500.5 ms, 1.001 s and 2.002 s of scheduled video time. These are not NTSC interlaced fields or measured end-to-end latency. The count is rounded and clamped once per video tick; nonfinite values become the one-frame default.

The video worker retains bounded immutable frame references tagged with their capture tick. At tick `t`, a count of `N` reads the capture from `t − N`; all delay reads happen before any current input is committed. Capture ticks are separate from the source frame's sequence metadata, so chained delays preserve source age. Missing history, including skipped capture ticks, produces transparent black. Repeated or backward renderer ticks clear history. A late completed tick still represents its scheduled tick; timing diagnostics continue to report lateness.

Reducing the count releases older captures; increasing it uses any retained capture of the requested age and otherwise produces black while history fills. Clear/reset empties history before reading, then captures the current input for future ticks. Bypass passes the input immediately, empties history and cannot break a zero-delay cycle; re-enabling starts cold. Missing input commits the defined black signal. Format/rate changes clear incompatible history, and removing the module retires its retained frames. The count is saved through normal Rack parameter storage; pixel history is not serialized.

The shared 512 MiB graph guard includes hidden delay history as well as outputs and working generations. It uses the larger of the actual retained-frame/current-work bound and a conservative capacity bound that allows a full requested history for each delay, bounded active CV sample histories, and current/retained working generations. The capacity bound may reject a graph whose current allocation is smaller, including multiple delays sharing source frames. The count is never silently reduced to fit. A graph that exceeds the guard reports a budget diagnostic; lowering a count or removing nodes must allow recovery. At 720×480, one unique RGBA float image is 5,529,600 bytes; 60 distinct images consume 331,776,000 bytes (about 316.4 MiB) before other graph resources. Frame-byte diagnostics count actual shared image pointers once; capacity reservation is not reported as allocated storage. Arbitrarily retained external generations and total process RSS remain separate accounting scopes.
