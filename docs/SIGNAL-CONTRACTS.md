# RVX signal, timing and feedback contracts

September 9, 2026. Issue #3 specification, reviewed against main `3eff9c0`. This sheet defines shared boundaries for the release plan and reconciles the existing prototype. It makes no source changes and grants no additional implementation approval.

**Status legend:** **I** is implemented behavior established by inspection of the named source; historical measured evidence remains in [VALIDATION.md](VALIDATION.md) at its own revisions. **P** is a proposed release contract requiring implementation and validation in its owning issue. **G** is an unresolved decision or empirical gate. A documented test is not a passing test, and an RVX mathematical model is not evidence of LZX circuit equivalence.

The [prototype contract](PROTOTYPE.md) remains authoritative for existing module indices, controls, normalizations and bypass behavior. This sheet supplies the shared vocabulary and future boundaries; it does not replace the [Memory Palace sheet](MEMORY-PALACE.md), [Syphon implementation notes](SYPHON.md), or [preliminary deferred waveform notes](VIDEO-AUDIO-ROUNDTRIP.md). Those sheets retain their distinct behavior and uncertainty.

## 1. Units and typed boundaries

| Domain | Values and units | Transport and conversion |
|---|---|---|
| Rack audio/CV (**I**) | Scalar Rack volts per engine sample; CV Bridge reads the first channel with `getVoltage()` | Ordinary Rack ports. No implicit image, pointer or composite protocol |
| Video signal field (**I**) | One float per active image position; nominal 0…1 video units (VU), with signed and above-range finite values | RVX `Field` port; explicit component extraction, grayscale construction or modulation |
| Working image (**I**) | Row-major RGBA float32; top-left origin; encoded RGB, straight alpha | RVX `Image` port, immutable shared frame references; explicit display/import/export conversion |
| Interlaced temporal field (**P**) | A scan interval with parity, ordered lines and sample time; not the scalar `Field` port above | Part of a declared raster profile; field assembly/deinterlacing is an explicit conversion |
| Composite/raster stream (**P**) | Ordered scalar samples, including active picture, blanking, sync and burst; composite amplitudes in IRE | Suite-owned typed stream with its own sample clock; encoder/receiver boundaries; no composite port exists in the prototype |

“Video field” in existing RVX ports means a **spatial scalar signal**, not half an interlaced frame. New APIs and UI must distinguish `SignalField` from `InterlacedField` rather than rely on context.

**P units:** define one VU as one nominal virtual video volt, with component black 0 VU and reference white 1 VU. This is an internal calibration convention, not a claim that every LZX port has the same electrical range, transfer function or impedance. Each module sheet must name the reference port and its actual conversion. Alpha is dimensionless coverage/key data, not an electrical voltage; coordinates and phase fields declare their role and units separately.

**I bridge law:** `u = s × v + o`, where `v` is Rack volts, `s` is VU/Rack V, and `o` is VU. Default `s=0.1`, `o=0`: −5 V → −0.5 VU, 0 V → 0 VU, +10 V → 1 VU, +15 V → 1.5 VU. Offset +0.5 maps a ±5 V waveform to 0…1 VU. Negative scale inverts polarity. No automatic rectification, normalization or DC removal occurs. Trigger mode instead emits unit fields 0 or 1, ignoring scale/offset. [Rack voltage conventions](https://vcvrack.com/manual/VoltageStandards) describe typical audio ±5 V and unipolar CV 0…10 V; these are conventions, not clipping limits.

**I arithmetic:** pointwise gain/mix preserves finite negative and above-white components; for example `2×0.8−0.25=1.35`, which a downstream gain of 0.5 can recover to 0.675. Clipping the intermediate would change that answer. Image mix preserves A's alpha, while explicit field-to-grayscale sets alpha to one. This utility is not a general alpha compositor. Invalid/missing image inputs resolve to transparent black; unpatched Processor field modulation is unity. An invalid connection reports its error before falling back to that consumer's declared empty-input behavior. No mismatched type is implicitly coerced. See [Video.hpp](../src/core/Video.hpp) and [Video.cpp](../src/core/Video.cpp).

**I/P boundaries:** current monitor/export clamps channels to 0…1 and Syphon uses an 8-bit transfer; internal frames remain float. Finite RGB at alpha zero remains meaningful for independently patched signal channels. General signal processing must not erase it through hidden premultiplication. Associated-alpha media filtering requires a named import/compositing profile and explicit straight/associated conversion, with zero-alpha behavior defined. Encoded video arithmetic is the proposed analog-inspired path; linear-light blending must be a separately named operation. **G (#5/#7/#8):** primaries, transfer, RGB↔component matrices, setup/range, alpha conversion and 480/486 crop conventions must be selected per boundary before color-fidelity claims. Current encoded RGB is not a complete color-management profile.

**P composite levels:** retain IRE as the separate stream unit. The existing [waveform notes](VIDEO-AUDIO-ROUNDTRIP.md#ports-levels-and-timing) preserve the preliminary mapping `0.05 Rack V/IRE`: blanking 0 V, sync −2 V, white +5 V, and a selectable setup convention. That law belongs to the deferred waveform bridge, not the existing `0.1 VU/Rack V` CV Bridge. #7 owns final composite levels/filter profiles; #16 cannot infer those from an image port or silently remove DC.

## 2. Identity, timestamps and clock domains

| Clock / identity | Contract |
|---|---|
| Video schedule (**I**) | Integer scheduled tick `k`, format numerator/denominator, and logical seconds `T(k)=k×1001/30000` for the default profile. Worker targets an absolute monotonic-clock origin; UI redraw does not advance video |
| Completed-image index (**P**, Memory Palace) | `n` increases only on successful image completion. `T[n]` records that image's scheduled boundary; gaps do not manufacture history |
| Source identity (**I**, limited metadata) | `Frame.sequence` and `Frame.seconds` describe frame provenance as supplied/generated; delay may preserve them. They are not universal capture tick, device exposure time or completed-image age |
| Rack engine sample (**I**) | Capture accumulates `ProcessArgs.sampleTime` into local audio seconds; nonconsecutive `ProcessArgs.frame` identifies a discontinuity. These are engine samples, not video frames |
| Audio device (**external**) | Device rate `Fd` and device block size belong to Rack Audio/Core Audio; they may differ from engine rate `Fa` |
| Stream epoch (**I** audio; **P** full transport) | A continuous capture run. Comparisons/interpolation across epochs are invalid; reset/gap information accompanies sample time |
| Raster clock (**P**) | Integer stream sample `q`, rational rate `Fr`, clock identity/epoch and origin. Derive line, field parity, frame and color phase from the profile; never reset oscillator/filter state merely because a processing block ends |
| Presentation/arrival (**I**, limited metadata) | Syphon arrival, worker completion and monitor redraw are independent observations. Repeating a displayed image does not assert a fresh camera exposure |

[Rack ProcessArgs](https://vcvrack.com/docs-v2/structrack_1_1engine_1_1Module_1_1ProcessArgs) documents `sampleRate`, `sampleTime` and the audio sample counter. [Rack Audio](https://vcvrack.com/manual/Core#Audio) distinguishes device and engine rates and describes resampling and block latency. Neither API supplies RVX with a Syphon/audio shared capture clock.

**P transport descriptor:** every future stream carries schema/profile version, type, dimensions/active rectangle, display aspect, channel/alpha/color convention, clock ID, epoch, integer sample or tick position, rational rate and source identity. Source sequence, source-arrival observation, scheduled processing tick and completion observation are distinct fields; unknown source capture timestamps stay unknown. A gap marker identifies missing intervals. Current `Frame` exposes dimensions, channels, sequence, seconds and pixels; it has no parity, display-aspect, rational timestamp or clock-ID fields. Do not overload its `seconds` to pretend those exist. Metadata expansion requires coordinated adapter/backend/history changes, not a documentation-only ABI change.

### Progressive and raster examples

**I default:** 720×480 progressive images at 30000/1001 ticks/s; one period is 33.366666… ms. Tick 30 is 1.001 s; tick 108000 is 3603.6 s. Rates are stored as a numerator/denominator and scheduled from absolute targets, avoiding accumulated rounding to 30 Hz. Derived `double` seconds and host deadlines still have finite precision; this is not an exact integer timestamp ABI or a genlock measurement.

**P NTSC-class profile:** the primary timing reference is SMPTE 170M-2004 distributed with [ITU-R BT.1700](https://www.itu.int/rec/R-REC-BT.1700-0-200502-I/en), §§11–13; the existing [rate-budget derivation](VIDEO-AUDIO-ROUNDTRIP.md#rate-budget-and-proposed-modes) records its application. `fsc=5 MHz×63/88`, line rate `2fsc/455≈15734.266 Hz`, 525 total lines, two interlaced fields, field rate `60000/1001`, frame rate `30000/1001`. A candidate `4fsc≈14.318 MHz` stream has 910 samples/line and 477750 samples/frame. Half-line offsets and the four-field color sequence must remain explicit; a line-by-line loop over 480 active rows cannot substitute for that timing. #7 must select active windows, field order, sync/burst placement and sample-phase origin before implementation.

**P conversion:** an image is active-picture data, not a total raster. Image→raster explicitly selects crop/resampling, field construction and whether both fields use one held progressive image. Holding one image for both fields preserves neither between-field source motion nor native interlaced capture. Raster→image assembles only validated complete output and declares weave/bob/other deinterlacing and its latency. Profile changes invalidate partial assemblies. Display aspect belongs to metadata/presentation and must not silently alter sample timing. #2/#5/#7 retain final SD geometry and field-cadence decisions; 720×480 is the current working canvas, not proof of a physical NTSC sampling grid.

## 3. Audio/CV bridges and event delivery

### A. Control and envelope modulation

**I latched CV:** the audio callback stores the newest voltage atomically; the worker reads one scalar for a whole image. Controls are observed when the renderer executes, so a late tick may read a value later than its scheduled boundary. There is no timestamped CV history, envelope follower or interpolation in this mode. Connecting an upstream Rack envelope supplies its output voltage, not a secretly implemented envelope detector. High-frequency input can alias at the image cadence.

**P release contract:** control snapshots choose the latest sample/event mapped at or before the declared consumption boundary and hold through that image. Envelope extraction, when offered, declares rectification/RMS/peak law, attack/release units and state separately from this transport. Optional control smoothing declares its time constant and reset value; it is never the waveform resampler. Timestamped history is required before promising exact boundary latching. Consumers include sliders, oscillator-rate controls and Memory Palace controls; full spatial AUX/key fields remain spatial.

### B. Buffered waveform-to-image sampling

**I CV Bridge mode 1:** capture timestamps belong to each module's continuous epoch. At the first available batch on video time `Tv0`, anchor its newest timestamp as `Ea0`; a tick at `Tv` requests `[E−D,E]`, where `E=Ea0+(Tv−Tv0)` and `D=1001/30000`. For row-major active pixel `p=yW+x`, `M=W×H`, sample time is `E−D+D×p/(M−1)` (for M=1 use the beginning). Adjacent audio samples are linearly interpolated, then scale/offset applied. Both endpoints are included; adjoining images can share a boundary sample. This deliberate image mapping has no blanking or interlaced timing.

Example: M=4 and a covered interval from 0 to 30 ms with `v(t)=100t` volts yields timestamps 0/10/20/30 ms and fields 0/0.1/0.2/0.3 at the default scale. At 48 kHz the default period spans 1601.6 engine sample intervals; it cannot be modeled as a fixed integer 1602-sample frame without timing error. Expanding roughly 1602 audio samples into 345600 pixels adds interpolated positions, not video bandwidth.

A usable interval requires continuous coverage, with implementation tolerance 1 ns; unavailable coverage emits **zero even with nonzero offset** and reports underrun. A captured batch may reanchor to its newest complete interval if the requested one is unavailable or the producer leads by more than one tick. Reanchors are counted and can jump waveform phase. After an actual stall, recovery needs a complete fresh interval beyond the last rendered endpoint; one new sample cannot replay an old partial image. Detailed recovery and bypass rules remain in [PROTOTYPE.md](PROTOTYPE.md). This is a buffered scan of audio history with approximate alignment, not seamless asynchronous resampling or capture-time synchronization.

### C. Continuous audio-as-voltage raster modulation

**P, distinct from B:** a raster operator evaluates one continuous audio timeline at every ordered raster position, including blanking where the operator applies. For video time `Tr(q)`, consume engine audio time `A(Tr(q)−L)`, using a declared positive lookback `L` and continuous mapping `A`. An initial validation profile uses one image period of lookback; changing it is a declared latency change. The resampler maintains phase/history across lines, fields and blocks; it never stretches a different audio window to fill each image or resets phase at row zero. Apply the same signed voltage law, preserving DC. Video→raster interpolation and audio reconstruction are separate operators.

A future drift controller may estimate relative rate in `A(t)=a×t+b`, but its filter, allowed correction, extra latency and discontinuity threshold need #3/#7 implementation validation before a seamless claim. The initial safe recovery contract is counted epoch restart with invalid/zero output until fresh coverage, not interpolation across a gap. A timestamped trigger affecting a raster operator is applied at the first stream sample at or after its mapped time; ordering is independent of render-block partitioning. Existing mode 1, despite continuous audio capture, does not implement this total-raster behavior. No new control/mode is added here.

### Bounded events and queues

**I:** `SpscQueue<AudioSample,32768>` has 32767 usable slots and drops newest on full; the worker retains at most 65536 audio samples. Capacities are counts, not guaranteed durations: the queue holds about 682.65 ms at 48 kHz or 341.32 ms at 96 kHz. CV Bridge pending triggers cap at 4096; excess is counted and one pending event produces one unit-valued image per tick. Adjacent events may therefore produce adjacent high images with no intervening low image: event preservation is a count promise, not a pulse-shape/timestamp promise. Inputs use Rack's Schmitt detector; physical/LZX threshold calibration remains module-specific. The producer counter is not an ordered event queue. Epoch/reset/bypass handling can deliberately discard the visible batch; no old batch may fire after reset. Frame Delay clear coalesces pending clear commands at the tick boundary. See [Modules.cpp](../src/rack/Modules.cpp) and the bridge state in [Video.cpp](../src/core/Video.cpp).

**P:** ordered release commands carry clock/epoch, sample timestamp, producer identity, sequence and command. Use bounded nonallocating queues, drop newest with a loss counter, and define same-time priority per consumer. Memory Palace's proposed 128-command queue and priority rules remain its own [control contract](MEMORY-PALACE.md#6-frame-sampling-motion-and-event-timing); do not replace them with CV Bridge's counter or cap. One-sample pulses captured between video ticks must survive if admitted and not invalidated by reset. Overflow is an explicit exception with diagnostics. Heavy allocation, locking against renderer work, file/SDK access and waiting remain outside the audio callback. A worker must consume finite snapshots/batches so an active producer cannot make a future processing pass unbounded.

## 4. Independent arrival, alignment and discontinuities

External video and audio remain separate: `Syphon → Video I/O → Processor`, with companion `Rack Audio/Core Audio → CV Bridge → Processor field`. Newest completed video can be held/repeated; each repeated presentation preserves source provenance. Audio-device loss does not reset the independent video scheduler, Test Image phase or Frame Delay. The current adapter starts a new CV capture epoch on rate changes, nonconsecutive Rack frames, audio-input cable transitions and queue-loss bursts; explicit module reset/patch restore has separate lifecycle effects. [Rack adapter evidence](RACK-ADAPTER.md) documents the supported API boundaries.

**P gap contract:** never interpolate across an epoch, splice partial composite frames or count a held picture as a new source capture. Invalidate incomplete temporal conversion state, report cause and losses, then require fresh coverage. Local conversion failure produces the type's declared empty result; explicit hold-last I/O is source-identity scoped. A source-selection change cannot inherit another source's held frame. Wall-clock changes are not video resets; elapsed scheduling uses a monotonic clock. Worker restart starts a new clock identity/epoch and cold history. Rate/format changes occur at one safe boundary with old data retired and new state marked cold. Independent clock drift/reanchoring does not silently rewrite a captured frame's timestamps.

**Latency accounting:** distinguish source capture→arrival (often unknown), device buffering/resampling, Rack cables/effects, bridge lookback, graph processing, output transport and display refresh. Rack documents one engine sample of delay per ordinary cable; at 48 kHz that is about 20.833 µs. This rule does not add an image tick per RVX video cable. A 512-sample device block at 48 kHz spans 10.667 ms; adding a 33.367 ms bridge interval gives 44.033 ms of those two durations alone, **not a measured total**. Buffers may overlap and upstream capture/output delays remain unknown. Sample/frame counters and independent arrivals cannot prove audiovisual alignment.

**G (#5/#13):** record matched audiovisual marker events with capture references, device/engine rates, block size, source cadence, worker epoch and receiver/display path. Measure baseline offset, variation, drift, reanchor jumps and recovery separately; report unknown timestamps. Repeat with rate mismatch and physical disconnect/reconnect. No current genlock, physical reconnect or end-to-end alignment result is inferred from the prototype's timing or standalone Syphon loopback evidence.

## 5. Causal graph, history and overload

**I image graph:** validate value identities and matching types from the immutable UI snapshot; order acyclic operators within one scheduled tick. Active Frame Delay reads old captures before current inputs commit; its input edge is a deferred state dependency. Video I/O receives before dependent operators and publishes after processing, so its source and sink halves do not create a false internal cycle. Unbroken same-tick cycles and unschedulable dependents get empty output plus diagnostics; independent schedulable branches can still run. Never choose arbitrary module order as a cycle solver. A bypassed delay is immediate pass-through and cannot legalize a cycle. Native cables provide editing/serialization, not analog propagation fidelity. [Adapter contract](RACK-ADAPTER.md), [renderer](../src/core/Video.cpp).

| History model | Exact age and gap rule |
|---|---|
| Frame Delay (**I**) | Integer N=1…60, default 1; tick k reads capture at k−N before all writes. Missing/skipped capture is transparent black; source sequence is separate |
| Memory Palace (**P**) | Ages count completed images n; a skipped scheduled slot consumes no age. Feedforward d=0 can use current input; proposed Warp/Paint recurrence uses max(1,d), visibly reporting the causal minimum |
| Raster delay (**P**) | Integer d≥1 stream samples at a declared profile rate; q reads q−d before writes. State persists across line/field/frame/block boundaries. Missing coverage/epoch change invalidates dependent state; output includes invalid/unlock status |
| External feedback (**I/P**) | Explicit host/application/transport latency, potentially varying; unknown time cannot be advertised as an exact frame/sample age |

Example with completed captures at scheduled ticks 0, 1, 3: at tick 3, Frame Delay N=1 requests tick 2 and returns black. Memory Palace completed-image age 1 requests the last completed image at tick 1. At tick 4, Frame Delay N=2 still requests missing tick 2. Neither history API may silently substitute the other's policy. At default cadence 1/15/30/60 scheduled ticks are 33.367 ms/500.5 ms/1.001 s/2.002 s. Chaining delays adds capture-tick ages when every requested capture exists, not source sequence numbers.

For an image recurrence `y[k]=x[k]+g×y[k−1]` with empty history, impulse x[0]=1 and g=0.5 gives 1, 0.5, 0.25, 0.125. Removing the delay rejects the cycle, even if an algebraic solution happens to exist. The identical recurrence in a future raster operator advances every stream sample, not every image. At candidate 4fsc, one raster sample is about 69.841 ns and one line is 910 samples; substituting a 33.367 ms image delay is not equivalent.

**I reset/resize:** Frame Delay clear/reset empties history before read and captures current input afterward; growth waits for missing ages, shrink drops older captures. Repeated/backward ticks and format/rate changes clear incompatible history. Bypass clears history, passes immediately and re-enables cold; removal releases it. Recall stores the count, not pixels. Memory Palace's Clear releases Freeze without erasing history, while Erase History is separate: its [lifecycle table](MEMORY-PALACE.md#7-history-delay-capture-and-lifecycle) must not inherit utility Clear semantics.

**I overload:** the scheduler skips stale scheduled ticks rather than catching up forever. Existing completed output remains available between renders; skipped ticks do not commit history. A completed late tick retains its scheduled identity. Rejected graphs may instead publish empty diagnostic state, so “hold last on all errors” is not the implementation contract. The shared 512 MiB guard refuses excess capacity without lowering resolution or delay; actual retained/current work and conservative requested capacity are distinct accounting scopes. Lowering counts/removing nodes allows recovery. One 720×480 RGBA float32 image is 5,529,600 bytes; 60 distinct images occupy 331,776,000 bytes (316.40625 MiB) before other resources. See [adjustable history](PROTOTYPE.md#adjustable-frame-delay-18).

**P raster overload:** bounded processing quanta may suspend while preserving sample order if the retained interval fits its fixed budget. Once required samples are skipped/lost, start a new epoch, invalidate partial images/filter/receiver state and reacquire. Do not evaluate a stateful filter once with an enlarged timestep and call it an equivalent scan, or replay an unbounded backlog. Named operators can provide analytic fast-forward only with an independently validated rule. Resource admission includes worst-case history, event/audio storage, resampling/filter state, old/new generations and backend buffers; total host RSS is reported separately. #2/#4/#7 select and measure budgets before release.

## 6. Precision, bandwidth and unsupported analog topologies

**I** CPU float32 is the arithmetic/reference backend; integer ticks plus floating derived time drive scheduling. Finite out-of-range values stay valid. Non-finite computed pixels are replaced with zero and counted; invalid audio samples are reported/skipped and non-finite parameters have documented fallbacks (Frame Delay count defaults to one). These repairs are numeric containment, not modeled saturation or an analog noise floor. Tests must reject non-finite comparisons explicitly. **P** a future raster state failure invalidates its dependent state/lock until reset or declared recovery rather than silently treating corrupted receiver state as good video.

**P** retain float32 for reference and precision-sensitive recursive/filter state. Float16 textures are an optional performance/storage candidate from the plan, not the current default. Before adoption, compare long feedback, near-threshold keys, signed ramps and oscillator drift against float32; record maximum error, state accumulation and any deliberate quantizer/saturation. Around unity binary16 spacing is 1/1024 and binary32 spacing is 1/8388608; these arithmetic scales do not specify a hardware converter's effective resolution. Spatial texture interpolation does not establish temporal filter response.

Each raster operator declares input/output bandwidth, sample rate, filter response/group delay, initialization, nonlinearity/oversampling and phase convention. Nonlinear gain limiting and hard keys can create harmonics above Nyquist; raising output image dimensions cannot undo upstream aliasing. Linear audio interpolation is not an ideal reconstruction filter. [Rack's DSP guide](https://vcvrack.com/manual/DSP#Sampling) explains sampling and prefiltering; #7/#8 must supply actual filter/convergence tolerances. At 48/96 kHz engine rates, Nyquist is 24/48 kHz; real NTSC has only about 3.051/6.101 engine samples per line. The existing deferred slowed-composite and coarse-raster proposals remain distinct from normal-time high-rate composite, with their original loss/slowdown limits.

Unsupported without a separate model and fidelity gate: instantaneous algebraic analog loops; arbitrary zero-delay oscillator/filter networks; bidirectional loading/impedance or power-rail coupling; uncontrolled propagation delays shorter than the selected sample interval; exact transistor-level saturation/noise; RF/physical composite wiring; physical genlock; and seamless phase recovery after missing samples. A restricted causal sampled recurrence can be supported and calibrated, but its declared latency is part of the behavior. A-grade feasibility, a plausible screenshot and native patch cords do not establish these equivalents. Close LZX control/port and analog behavior remains a requirement; each unsupported reference topology must be recorded in its module sheet, never silently replaced by whole-frame feedback or a generic VHS effect.

Numeric arithmetic fixtures use finite checks and absolute tolerance ≤1e−6 for normalized float32 pointwise/interpolation values; integer IDs, event counts and history validity compare exactly. | Shared boundary | Consumers / owning follow-up | Required coordinated change |

| Units/types/alpha/color | Processor, Test Image, CV Bridge; component/core modules #8; I/O #5; NTSC #7 | Update converters and consumer normalizations together; signed/alpha fixtures prevent silent clipping |

| History service | Frame Delay #18; Memory Palace; future raster delay | Share immutable storage/admission/read-before-commit primitives; retain explicit scheduled-tick, completed-image or raster-sample age policy |

| Deferred waveform #16 | Later Encoder/Receiver adapters, ordinary Rack chain, optional memory integration | Consume settled #3/#5/#7 contracts; preserve slowed composite/coarse raster/high-rate identities and all release choices |
| Acceptance/integration | #9 release plan, #13 prototype, #30 native panel work | A spec merge does not pass empirical gates, alter panel/port IDs or expand coding scope |

The existing core/Rack/backend boundaries should be reused. Do not introduce parallel per-panel clocks, voltage converters or history engines; equally, do not force different history ages or module control laws into one hidden default. Before changing any shared contract, audit every open issue, name all affected consumers, version persisted semantics when necessary, update their authoritative sheets and numeric fixtures, then obtain fresh review of the integrated implementation.

**Remaining G decisions:** #2 confirms full-release Mac/DAW target, active geometry and performance profile; #4 settles renderer and broader lifecycle proof; #5 settles import/export color/alpha, source behavior and measured alignment; #7 selects total raster/levels/filters and receiver lock/convergence tolerances; #8 selects/calibrates each LZX module; #9 integrates release scope and coding approval. Memory Palace U1–U6 remain unresolved, including field versus frame recursion and displayed-zero delay. Timestamped controls/events, continuous raster modulation and extended transport metadata above are proposed interfaces, not shipped features.

**Deferred order remains unchanged:** finish #13 including its open empirical gates → settle #3 and #5 → complete #7 specification and sequence its implementation → #9 release placement and explicit coding approval → implement #16. Memory Palace coordination is optional for its later feedback integration. Completing this shared specification is possible while downstream empirical/profile decisions remain explicit; it neither starts #16 nor closes those issues.
