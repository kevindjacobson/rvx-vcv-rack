# RVX video ↔ audio waveform requirement

September 7, 2026. **Requirement:** convert video into an ordinary Rack audio waveform, process it with audio modules, and reconstruct video with NTSC-like behavior. This sheet addresses issue #16; it informs signal/raster timing and feedback #3, Syphon #5, composite #7, the complete pre-code plan #9 and Memory Palace #6. All modes, controls and gates below are **proposals**, not implemented or measured capabilities. The wider NTSC specification remains in #7.

## Rate budget and proposed modes

SMPTE 170M-2004, distributed with [ITU-R BT.1700](https://www.itu.int/rec/R-REC-BT.1700-0-200502-I/en), §§11–13, specifies `fsc = 5 MHz × 63/88`, `fH = 2fsc/455`, 525 lines/frame and two interlaced fields/frame. Thus `fH ≈ 15,734.266 Hz`, `fField = 60000/1001 Hz`, `fFrame = 30000/1001 Hz`, and one line lasts about 63.556 µs. Its §7 distinguishes unrestricted studio luma bandwidth from the typical 4.2 MHz broadcast limit. We use **4.2 MHz as a bounded example profile**, not a universal NTSC bandwidth ceiling; [Analog Devices' Video Basics, Table 1](https://www.analog.com/en/resources/technical-articles/basics-of-analog-video.html) corroborates that example.

Let `Fa` be Rack's **engine** sample rate. Each ordinary mono cable carries one scalar per engine sample; the audio device can run at another rate and introduce conversion and buffering. [Rack Core manual](https://vcvrack.com/manual/Core#Audio). Nyquist requires bandwidth below `Fa/2`, with practical transition space for filtering. [Rack DSP guide](https://vcvrack.com/manual/DSP). Derived arithmetic:

| Quantity | 48 kHz engine | 96 kHz engine |
|---|---:|---:|
| Nyquist limit | 24 kHz | 48 kHz |
| Samples per real NTSC line, `Fa/fH` | 3.051 | 6.101 |
| Samples per real NTSC frame, `Fa/fFrame` | 1,601.6 | 3,203.2 |
| Slowdown required for 4.2 MHz, `S > 2B/Fa` | >175 | >87.5 |
| Proposed example slowdown `S` | 256 | 128 |
| Scaled bandwidth / subcarrier | 16.406 / 13.983 kHz | 32.813 / 27.965 kHz |
| Scaled line rate / frame duration | 61.462 Hz / 8.542 s | 122.924 Hz / 4.271 s |

**A — Slowed composite.** For virtual NTSC time `tv` and elapsed audio time `ta`, `tv=ta/S`; encode `w(ta)=g×(0.05 V/IRE)×c(ta/S)+o`, with composite `c` in IRE, dimensionless gain `g` and offset `o` in Rack volts. Every frequency divides by `S`, every duration multiplies by `S`, including sync, burst and receiver acquisition constants. The effective sampling rate in virtual video time is `Fa×S` (12.288 MHz for both examples). S=256 is the common baseline at both engine rates; S=128 is an additional 96 kHz profile. Changing sample rate must not silently change S. Bandlimit before reducing sample rate and interpolate the waveform explicitly on reconstruction.

Time scaling is invertible for a chosen bandlimited waveform with known scale, intact timing and a clean transport, subject to resampling error. This does **not** imply lossless original RGB recovery: encoding filters, chroma/luma separation, image resampling and discarded alpha already limit it. All blanking, negative sync, burst, field parity and color-frame phase belong in the waveform; no image data is secretly sent around the audio chain.

Default live-input policy captures the newest completed image at each **slow frame start**, holding it for that entire scan, including both fields. Source motion is therefore heavily decimated and has no between-field motion. Preserving a full-speed source sequence would require bounded recording followed by slowed playback; recording/media scope remains unresolved. A completed decoded frame publishes only after assembly; Syphon and monitors repeat the previous image between arrivals.

**B — Real-time coarse raster.** Keep `30000/1001` image updates/s, but scan a deliberately reduced grayscale image progressively with custom line/frame sync. A candidate 32×32 grid needs `1024×30000/1001 ≈ 30,689` scalar positions/s; reserving 25% of total time for timing gives about 40,919 positions/s. This fits the 48 kHz sample-count budget before filter quality is assessed; it is not proof of 32×32 independent resolved detail. Both image axes need prefiltering; decoder interpolation adds no information. This mode has negative sync and blanking but **no colorburst**, NTSC interlace or NTSC chroma carrier. It is raster sonification with NTSC-inspired failure behavior. A future color variant needs its own bandwidth allocation and identity.

**C — High-rate RVX composite.** Retain the suite-owned composite/raster domain for normal-time color and dirty mixing. A candidate `4fsc ≈ 14.318 MHz` has 910 total samples/line; rate, filters and nonlinear oversampling need convergence/performance gates. It is never an ordinary 48/96 kHz voltage wire. Explicit bridges perform time scaling or coarse scanning; stereo/polyphony does not automatically make stock audio effects process video bandwidth. Rack documents custom higher-rate polyphonic protocols as a possibility, but arbitrary modules would need protocol support. [Rack Polyphony manual](https://vcvrack.com/manual/Polyphony#Other-uses).

## Ports, levels and timing

Proposed **Video → Waveform**: typed Image input; ordinary mono WAVE output; mode/profile, S, gain, offset and polarity controls; shared/independent source clock and drift/phase settings; Capture/Reset inputs. Capture switches to a held image at the next scan-frame boundary; subsequent Capture events replace it, and Live resumes automatic snapshots. Reset restarts raster phase and clears partial state. Proposed **Waveform → Video**: ordinary mono WAVE input; typed Image output; matching profile/S, input gain/offset/polarity, waveform/shared timing selector, clamp, lock sensitivity and reacquisition controls; H/V/color-lock and stream-gap indicators. Use separate typed COMPOSITE ports for mode C. Unpatched encoder input emits black with valid timing; an unpatched receiver reports unlock and outputs black. Receiver output alpha is one; encoder alpha is flattened against a declared black background.

Initial mapping is `0.05 Rack V/IRE`: blanking 0 V, sync −2 V, reference white +5 V, burst ±1 V about blanking; black is +0.375 V for 7.5-IRE setup or 0 V for the explicitly selected zero-setup profile. These IRE levels follow SMPTE 170M §12/Table 1; Rack scaling is our choice. Preserve finite chroma overshoot and negative excursions. Gain=1, offset=0 and positive polarity are defaults; inversion includes sync and burst. No automatic normalization or DC removal is allowed. Rack convention typically uses ±5 V audio, and each cable adds one sample of delay. [Rack Voltage Standards](https://vcvrack.com/manual/VoltageStandards).

DC-blocking effects can remove pedestal and distort slow timing pulses; a receiver back-porch clamp can estimate offset only while usable timing survives. Clipping, gating and heavy filtering can erase timing entirely. These are intended processing possibilities, not guarantees of successful decoding through every effect. Stereo may carry two independent mono streams, or an explicitly selected waveform plus clean reference on a second cable; it is not twice the mono bandwidth. WAVE reads channel 1 and reports extra channels rather than summing unrelated timing streams.

Default receiver timing is **recovered from WAVE**, including burst in mode A. An optional clean RVX shared reference is a visibly labeled assisted mode with explicit transport-delay alignment; it cannot pass dirty-lock tests. Separate source oscillators may drift in frequency/phase. Mix them on one audio timeline with known nominal profiles; never synchronize their images before mixing. Delay changes affect line position and relative burst phase. Gain, offset, inversion, clipping, filtering and summed sync can cause tearing, rolling, chroma cancellation and loss/recovery of color lock. Noise and drift fixtures use reproducible seeds.

Audio time, virtual raster time, source-image arrival and completed-image publication are distinct. Reset, cable discontinuity, rate change or queue loss starts a new epoch, clears partial frames and relocks; never interpolate across missing samples. Default gap output is black with status, with explicit hold-last as an option. Encoder/receiver bypass outputs zero/black and invalidates partial state. Bounded queues join the audio callback to the video worker; buffer creation, frame rendering and waits stay off audio processing. Total latency includes cables, effects, resampling filters, queues and frame assembly.

## Reference patch and acceptance gates

Baseline: `Test Image → Video-to-Waveform A → unity DC-preserving utility → Waveform-to-Video A → Monitor / Syphon`; split WAVE to a scope and compare against the high-rate clean encode/decode reference. Use 48 kHz, S=256, waveform recovery, standard setup, noise/drift off, constant bars plus numbered frames. No audio hardware playback is required. Then insert a filter, polarity/offset control and a second independently timed encoded source into the audio mixer.

These future tests require saved profiles, source fixtures, sample timestamps and declared tolerances before execution:

1. **Clean round trip:** after documented acquisition, preserve scan/field order and bars within specified encode/decode error; independently verify waveform, pedestal, burst and 8.541867-second frame spacing. Align known latency before comparison; a self-generated image alone cannot establish hardware fidelity.
2. **Rate relationship:** repeat S=256 at 96 kHz; duration stays fixed and virtual sampling improves. At S=128, verify 4.270933 seconds/frame. Test fractional sample boundaries and long-run rational timing without phase resets per image.
3. **Information limits:** spatial multiburst/edges show declared filtering in A and reduced resolution in B; sweep beyond Nyquist and record alias rejection. Deliberately nonlinear third-party effects may alias; upsampling at the decoder cannot repair lost data.
4. **Damaged timing:** sweep attenuation, offset, inversion, delay and independent-clock mixing; record loss thresholds, holdover and reacquisition time in both virtual and wall seconds. Suppress burst while retaining sync and verify independent color-lock loss. Shared timing must fail eligibility for this test.
5. **Causality and lifecycle:** deletion, bypass, reconnect, missing source, rate changes and queue overflow cannot replay partial history or block audio; count losses and measure end-to-end latency and bounded memory.
6. **Memory integration:** put encode/process/decode inside an explicit delayed feedback loop. Keep Memory Palace's image-history ticks separate from slow raster frames; repeated display images do not imply newly captured source frames. Verify accumulated damage and measured loop age. A single audio-cable delay cannot satisfy the image graph's causal-delay rule.

Integration evidence is limited: the separately approved issue #13 prototype (`2a077dd`, `docs/PROTOTYPE.md`) has buffered audio-to-raster conversion, not waveform encoding or sync recovery. The Memory Palace proposal (`bd8620`) separates completed-image history from source arrival and unresolved hardware field recursion. This sheet extends those boundaries without changing the prototype or implementing the Memory Palace proposal. Open choices are receiver/filter tolerances, mode B timing layout and usable resolution, media sequence handling, CV laws/ranges and mode C's measured rate budget. No NTSC hardware-equivalence claim or physical composite/audio-interface transport is established.
