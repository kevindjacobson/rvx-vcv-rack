# Syphon backend

The prototype uses the official [Syphon Framework](https://github.com/Syphon/Syphon-Framework) at commit [`71351d4b484cd2d1917867f7846a5cdca724552d`](https://github.com/Syphon/Syphon-Framework/commit/71351d4b484cd2d1917867f7846a5cdca724552d). The source is distributed under Syphon's BSD-style license. The distributable notice is `licenses/Syphon.txt`; `scripts/fetch-syphon.sh` also copies it to `dep/Syphon/LICENSE.txt` beside the local build.

Run `scripts/fetch-syphon.sh` from anywhere in the checkout. It downloads the pinned archive, verifies SHA-256 `9196aceb663bc87a3d9981fb993135cafb23a7df7a832d4cac5138925b6bbb1d`, and creates the ignored files `dep/Syphon/libSyphon.a` and `dep/Syphon/include/Syphon/*.h`. Link the archive with `-Wl,-force_load,dep/Syphon/libSyphon.a` and the Foundation, AppKit, OpenGL, IOSurface and CoreVideo frameworks. Force-loading is needed because the archive contains Objective-C classes and categories that a normal static link may discard. The dependency sources compile for arm64 with the selected macOS SDK, a default deployment target of 11.0, and `-O2 -DNDEBUG -fobjc-arc -fblocks -DSYPHON_CORE_SHARE -DGL_SILENCE_DEPRECATION`; `dep/Syphon/BUILD-INFO.txt` records the exact local compiler, SDK, target and flags.

The upstream SDK 5 release contains an x86_64-only framework, so it is not the RVX dependency. Current upstream source includes Metal APIs, but its Metal server loads a compiled default Metal library from its bundle. This machine has Apple Command Line Tools and no `xcodebuild`, `metal` or `metallib` tool, so the prototype deliberately compiles upstream's OpenGL client/server and shared messaging sources with `SYPHON_CORE_SHARE`. Metal support is not present in this build.

OpenGL is deprecated on macOS but remains present on the prototype target. The pinned source also uses the deprecated global-IOSurface compatibility key required by its transport and produces a compiler warning on the macOS 26 SDK. The static archive retains Syphon's Objective-C class names; coexistence with a different Syphon library loaded into the same Rack process is an unverified packaging risk and must be tested before release.

Each RVX Video I/O backend owns a CGL 3.2 core-profile context and is created, called and destroyed on the video worker. Syphon uses private contexts shared with that owned context. The Rack audio callback and monitor draw path never call Syphon or OpenGL. The backend polls `hasNewFrame`; it does not install Syphon's callback, which may run on another thread.

`sources()` copies the shared server directory into plain C++ values. A live selection first matches the saved Syphon UUID. If it disappears, exactly one matching application/server name reconnects and adopts the restarted stream for the running session. Duplicate application/name matches are reported as ambiguous. Source lists and IDs are snapshots: Syphon documents names as non-unique and UUID as the only programmatic instance identity, when present.

Input is attached to a read framebuffer and read back from Syphon's BGRA8 IOSurface texture as normalized RGBA floats, vertically converted from OpenGL's bottom-left origin to RVX's top-left origin, then nearest-neighbor stretched to the requested working format. This explicit prototype policy does not preserve aspect ratio. A missing input returns no frame, or the last complete frame when `holdLast` is enabled.

Output clamps finite values to `[0, 1]`, maps non-finite values to zero, quantizes to RGBA8, and preserves straight alpha. It uploads the top-left CPU rows to an owned GL texture and asks Syphon to flip during publication. The published transport is therefore 8-bit normalized even though RVX processing remains unclipped float. Syphon publication and input readback add GPU copies; the prototype makes no zero-copy or SD GPU-processing claim.

The command-line loopback in `tests/syphon_test.mm` creates independent publisher and receiver backends, discovers the server, checks RGBA and orientation, relays a received frame while the input client remains active, resizes the live source, verifies missing-source and hold-last behavior, reconnects after a new UUID appears under the saved application/server names, and rejects an ambiguous duplicate name. It pumps the Foundation run loop while waiting for distributed discovery notifications, matching the AppKit run loop available in Rack standalone.
